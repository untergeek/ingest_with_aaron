# Generate Fleet Certificates for Logstash

As documented [here](https://www.elastic.co/guide/en/fleet/8.16/secure-logstash-connections.html).

# Get certutil

We do this by downloading Elasticsearch somewhere. We don't need to run it, we just need to have access to the `certutil` binary.

```
wget https://artifacts.elastic.co/downloads/elasticsearch/elasticsearch-8.16.1-linux-x86_64.tar.gz
tar zxf elasticsearch-8.16.1-linux-x86_64.tar.gz
cd elasticsearch-8.16.1/
```

Please note, Mac users: The newest versions of macOS might block you from executing Java if it is not recognized yet as "safe"

# Create a CA Certificate

These steps all assume you are in the expanded `elasticsearch-X.Y.Z` directory

```
./bin/elasticsearch-certutil ca --pem
```

The resulting output:

```
This tool assists you in the generation of X.509 certificates and certificate
signing requests for use with SSL/TLS in the Elastic stack.

The 'ca' mode generates a new 'certificate authority'
This will create a new X.509 certificate and private key that can be used
to sign certificate when running in 'cert' mode.

Use the 'ca-dn' option if you wish to configure the 'distinguished name'
of the certificate authority

By default the 'ca' mode produces a single PKCS#12 output file which holds:
    * The CA certificate
    * The CA's private key

If you elect to generate PEM format certificates (the -pem option), then the output will
be a zip file containing individual files for the CA certificate and private key

Please enter the desired output file [elastic-stack-ca.zip]:
```

Accept the default value, `elastic-stack-ca.zip` by pressing return. You can name it differently, if you choose. Be sure to specify the name you chose in the following `unzip` block.

## Unzip the resulting output file 

You must `unzip` this file as you will need the contents

```
unzip elastic-stack-ca.zip                                                                                            
Archive:  elastic-stack-ca.zip
   creating: ca/
  inflating: ca/ca.crt
  inflating: ca/ca.key
```

Note that the path is simply `ca` because it's a CA certificate from the `ca` subcommand.

# Generate a client SSL certificate signed by your CA

This `client` certificate will be used by Fleet to verify the certificate that will be installed in Logstash

```
./bin/elasticsearch-certutil cert \
  --name client \
  --ca-cert ca/ca.crt \
  --ca-key ca/ca.key \
  --pem
```

The resulting output:


## Unzip the resulting output file 

You must `unzip` this file as you will need the contents, which will be pasted into the web form in Fleet settings.

Note that we used the manually specified `client-bundle.zip` file name

```
unzip client-bundle.zip                                                                                               Archive:  client-bundle.zip
   creating: client/
  inflating: client/client.crt
  inflating: client/client.key
```

Note that the path is the value from `--name`, which is `client`.

# Generate a Logstash SSL certificate signed by your CA

The resulting certificate will be used by Logstash.

You **_must_** replace `your.host.name.here` and `192.0.2.1` with your respective values. If you do not have an FQDN value for `--dns` you should omit that line and just have an IP. I do not recommend this approach, but manually specifying the IP here should work. 

If you plan on having multiple Logstash instances, **_you should expect to put them behind a load balancer of some kind_** as Fleet will only connect to a single FQDN or IP address.

```
./bin/elasticsearch-certutil cert \
  --name logstash \
  --ca-cert ca/ca.crt \
  --ca-key ca/ca.key \
  --dns your.host.name.here \
  --ip 192.0.2.1 \
  --pem
```

## Unzip the resulting output file 

You must `unzip` this file as you will need to convert the private key to pkcs8 format, as well as copy these files to your Logstash instance.

Note that we used the manually specified `logstash-certs.zip` file name:

```
unzip logstash-certs.zip                                                                                              Archive:  logstash-certs.zip
   creating: logstash/
  inflating: logstash/logstash.crt
  inflating: logstash/logstash.key
```

Note that the path is the value from `--name`, which in this case was `logstash`. 

## Convert the Logstash private key to pcks8 format

First, navigate to the `logstash` subdirectory you just extracted:

```
cd logstash
```

On a Linux or macOS host (if `openssl` is installed), the command is:

```
openssl pkcs8 -inform PEM -in logstash.key -topk8 -nocrypt -outform PEM -out logstash.pkcs8.key
```

You can verify existence and values:

```
$ ls                                                                                                                  logstash.crt       logstash.key       logstash.pkcs8.key
$ file logstash.key                                                                                                   logstash.key: PEM RSA private key
$ file logstash.pkcs8.key                                                                                             logstash.pkcs8.key: ASCII text
$ cat logstash.pkcs8.key                                                                                              -----BEGIN PRIVATE KEY-----
<....PRIVATE KEY DATA....>
-----END PRIVATE KEY-----
```

# Copy certificates to Logstash host

You will need to copy the following files to your Logstash host:

-  `ca/ca.crt` 
- `logstash/logstash.crt` 
- `logstash/logstash.pkcs8.key` 

Be sure they are in a path where the `logstash` user (the user executing the `logstash` process) has read access.

You still need to protect these keys like you would any other.
